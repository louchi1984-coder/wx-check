# 批量 UI 检测

## 工具调用与核验

调用路径和当前进程的环境配置见[工具细节](tool-details.md)。机型、页面与状态由执行者选择，先读取本轮连接信息，沿用代码测试的工程、端口与CLI身份；几何与截图由工具辅助，显示是否正常仍须实际读图和按疑点操作。

| 检查目标 | 调用工具 | 怎样确认结果 | 失败后怎么办 |
| --- | --- | --- | --- |
| 当前目录与完整机型计划 | ui-check.mjs --plan；设置六款WECHATIDE_PRECISE_MODELS后再次--plan | 六款精测、其余最小检查及宽屏重点均在计划中 | 目录或分组异常先核对实际配置，不自行缩为少数机型 |
| 批量通道 | check-debug-channel.mjs只读探活；确未开启时按[通道说明](debug-channel.md)准备 | ready、projectMatches为1且protocol.available为true，复用代码测试已验证的实际端口 | 只停止依赖它的批量切换；官方当前机型检查可继续，多机型缺口仍保留 |
| 同窗口切换与采集 | ui-check.mjs --matrix，--debug-port为实际端口，--out在工程外 | 实际尺寸与机型匹配；逐页采集，核对failures、unvisited和restoration | 保存已完成结果和恢复情况；单页或单机型失败记录后继续其他独立检查；共享通道不可用时停止依赖它的操作 |
| 图片、截断、重叠、遮挡及布局 | 实际读图；按疑点用官方元素/滚动/输入接口补查 | 精测图片逐张有结论，必要滚动与键盘状态实际核对 | 仅保存图或几何无告警不算完成；未读图、未执行状态逐项列缺口 |

完整命令见下方“独立命令”。脚本report.json/report.md是采集附件；计划未执行、采集失败或精测图未读完时，只能交付部分完成的UI报告，不能以当前机型检查替代整套计划。

## 覆盖计划

小、中、大各两款精测，其余机型做最小必要检查。先运行`node scripts/ui-check.mjs --project <源码> --plan`读取当前工程机型目录，再由执行者按实际可用尺寸选择较新代表，包含折叠展开／宽而短的屏幕，不固定作者机器的型号。

设置WECHATIDE_PRECISE_MODELS为六个完整名称的JSON数组，顺序小、小、中、中、大、大。再运行--plan核对分组，--matrix执行该计划；未配置六款时--plan只列目录，--matrix明确报错。指定--devices可单独采集所选机型，不要求先选齐六款；不要求用户拥有对应实体手机。

## 执行顺序与范围

1. 代码版本不变时，编译和工程静态检查只做一次，作为准备证据；用户已选代码测试时可复用到代码测试结果，不能因此宣称完成代码测试。后续 UI 命令不编译、不刷新、不重新读所有诊断面板。
2. 切换目标机型后，先读取真实屏幕和内容尺寸。必须匹配预期屏幕尺寸，连续两次一致才开始；不用固定长等待，不套默认尺寸。
3. 每页先导航，再一次读取全部 class 的元素位置，同时核对实际页面路径和尺寸。精测对比两次布局采样；仍有变化时保存截图并标记需读图判断，执行者区分动画与布局问题，按疑点补查；不因空列表里的 class 没元素就重复采集。
4. 六个精测机型每页／必要状态保留一张截图，直接嵌入报告；其他机型的重叠、截断、遮挡等显示问题，有异常线索才截图复核；记录显示状态，未测项不算通过。同一问题跨机型合并，保留受影响机型及证据。
5. 整批结束通过 finally 恢复原机型与原页面，并验证实际运行结果。中途失败也恢复；只改目标项目机型字段，其他设置保持当前值。恢复失败明确报告并保留工程外备份。

| 范围 | 要做什么 | 不重复做什么 |
| --- | --- | --- |
| 六个精测机型 | 稳定布局；溢出、重叠、截断、关键按钮遮挡；有需要的页面检查滚动和键盘遮挡 | 代码测试编译；无业务意义的逐按钮点击；完整保存业务流程 |
| 其余机型 | 溢出、重叠、截断、关键按钮遮挡的最小检查，异常才截图核实 | 完整状态遍历、重复截图审阅、重复根因分析 |

滚动和键盘测试围绕相关页面做；最小屏幕优先，六个精测机型按安全区域和布局差异补充，不机械重复相同操作。长文本、大金额、有数据与空数据按实际界面风险选必要状态，不写入用户真实数据来凑覆盖。无测试数据时标明未覆盖。

横向滚动内容超出容器是正常设计，先核对运行时scrollX和实际裁剪范围。采集脚本在同次查询中读取可定位scroll-view的当前属性及后代矩形：容器在屏幕内且启用横向滚动时，其后代不报屏幕溢出；容器本身越界、滚动关闭或容器外同类名元素仍检查。只有静态标签、无法定位或运行时属性未确认时不能自动豁免，也不能直接认作应用缺陷；按实际结构补查。触控区偏小只作精测优化线索，不因这一项给每个最小检查机型补截图。

## 精测截图必须读图

采集完成后，由执行者逐张审阅六款精测机型的页面截图；可由能读图的 AI 或人工完成，不依赖特定平台。复用本轮已有图片，不为审阅重新切机型或截图。报告逐页记录“已读图／未读图”，注明截图时间和页面状态；未读图不能称精测完成。

按机型与页面记录简短审阅结论，工具支持时可一次读取多张图片。已确认的同一误报或根因保留结论并关联受影响机型，不对每款重新推演。原图可直接用于报告，不为整理复制整套图片再重读；仅在出现新差异、证据矛盾或图片不清时针对性补查。UI过程中不回头重测已有可靠证据的业务流程。

除了截断、重叠、遮挡，还要看布局感受：文字与卡片比例、主次层级、留白与信息密度、关键操作位置。感受必须落到具体可见现象及使用影响，统一使用“需要修复”“建议优化”“待确认”并说明理由，附对应截图；不能只写“看起来正常”。

折叠屏展开／宽而短的窗口必须作为独立重点，与普通竖屏对照：是否只是把文字、间距、卡片整体放大；首屏是否仍能看到核心信息与操作；宽度有没有合理利用。按问题建议限制内容宽度、控制字号间距或分栏，不强制所有页面采用同一方案。静态展开机型不能证明折叠切换时状态保持正常。

首屏看不到按钮，要写“首屏不可见”，不能直接判定永久遮挡或无法操作。滚动可达性、键盘影响和点击结果另行核验；只有具体疑点需要动态验证时才补采必要状态。空数据截图不能证明长文本、大金额和有数据状态正常。同类问题跨机型合并，保留各页的具体表现。

## 独立命令

需要 Node、wechatide，以及已登录、已打开目标项目的微信开发者工具；不需要 Codex 或其他 AI 平台。CLI 客户端由 `WECHATIDE_CLIENT` 指定（默认 miniprogram-autocheck；沿用已有授权客户端时设置其实际名称）。

```bash
# 先读本机目录并选择六个实际机型名称；下列占位名称须替换
node scripts/ui-check.mjs --project /path/to/source --plan
export WECHATIDE_PRECISE_MODELS='["小屏机型1","小屏机型2","中屏机型1","中屏机型2","大屏机型1","大屏机型2"]'
# Windows PowerShell中用 $env:WECHATIDE_PRECISE_MODELS='[...]' 设置同一JSON数组
node scripts/ui-check.mjs --project /path/to/source --plan

# 自动执行本机计划：六个精测，其余最小检查
node scripts/ui-check.mjs --project /path/to/source --matrix --out /path/out/matrix

# 自动切换指定机型，结束恢复原机型
node scripts/ui-check.mjs --project /path/to/source --devices "HUAWEI Mate 80" "iPhone 15 Pro Max" --out /path/out/subset

# 只对当前尺寸检测，屏幕尺寸必须真实匹配
node scripts/ui-check.mjs --project /path/to/source --expected-size 320x568 --mode precise --out /path/out/small
node scripts/ui-check.mjs --project /path/to/source --expected-size 390x844 --mode minimal --out /path/out/medium

# 汇总同一个工程不同机型的原始 report.json
node scripts/ui-check.mjs --merge /path/out/small/report.json /path/out/medium/report.json --out /path/out/summary
```

命令从skill目录运行，或使用脚本绝对路径。六款配置必须传给后续--plan及--matrix的执行进程，不能假定不同工具调用共享export；通用运行时与路径配置见[工具说明](tool-details.md)。--page <实际页面路由>可限定采集页面；--devices的默认是精测采集，可用--mode minimal只补指定机型的最小检查。

每次使用独立输出目录。报告和截图必须放到工程之外，避免检测文件触发热重载。精测每页保留一张图并内嵌到 Markdown 报告；最小检查的正常页不截图，显示异常／采集异常才截图。已有截图只在尺寸、状态与代码版本适用时复用，并注明原拍摄时间；不同采集时间不能冒充同轮证据。

使用当前调用工具的有界时限；单页读取失败保留缺口并继续其他页面；共享通道确不可用时停止有关操作，不按每个class轮流等待。布局仍变化时保留截图供判断，不能直接判通过；最小检查保持每页一次采集。单次响应过大时先报采集不完整，按明确报错有针对性缩小采集，不能把超时当成数据过大盲目二分重试。

退出码：0 几何采集完成且无 P0；1 有确定横向溢出；2 参数错误／采集不完整。退出码 0 不表示全部 UI 项目通过。

## 当前实现的边界

`ui-check.mjs` 自动完成：实际尺寸与页面核对、整页 class 矩形、横向溢出、触控区、精测布局稳定性、异常截图、耗时记录和跨机型问题合并。

它**尚不自动判定**文字截断、元素重叠、关键按钮被遮挡，也不自动操作滚动或键盘。不能把容器和子元素正常重合误判为遮挡，也不能把需要滚动的按钮误判为永久不可见。以上按必要页面补充核验后才能写入完整精测结论；按疑点通过当前官方接口补查，不在每个机型无差别重跑。

默认使用运行中切换：通过本机 CDP 连接定位目标项目窗口，调用开发者工具自己的 `toolbar.selectDevice`，复用它现有的 Automator 桥接完成导航、尺寸读取、采集及模拟器截图。整批共用一个连接，不点击 GUI，不逐机型启动 CLI，不关闭重开窗口，不修改应用安装包。必须用实际机型、屏幕尺寸及像素密度连续两次稳定匹配后检测；返回成功本身不算验证。

这里使用工具内部模块，版本升级后入口可能变化；模块不匹配就停止，不能退回伪造运行数据或静默重开。需要 Node 22 或更新版本及工具的本机调试端口（默认 9223；`--debug-port` 或 `WECHATIDE_DEBUG_PORT` 可指定）。不依赖 Codex 或其他 AI 平台。

首次准备统一按[本机调试通道](debug-channel.md)执行只读检查、授权启动和参数核验；代码诊断与UI共用同一实际端口。已有可连接的进程直接复用，整批不重启。检查被当前执行通道限制时核对已获准的其他系统执行能力；真实启动失败保留错误，避免重复启动。

整批先生成计划，逐个切换并保存独立报告；单页、单机型采集失败保留缺口并继续其他机型；共享通道不可用时停止依赖它的操作，已完成结果仍保存，未执行机型明确列出。原机型与页面在 finally 恢复并核验；恢复探测有上限，失败时给出备份位置。就绪后的实测信息直接传给 UI 采集，不重复两次就绪探测，也不在每个机型结束时重复恢复页面。

## 面向普通人的报告

先写“哪些页面／机型测过、发现什么、是否建议修复、哪些还没测”；技术尺寸、元素数量、耗时放在原始 JSON。布局感受须有可见事实与使用影响，不臆造乱码或泛泛评价审美，也不把异常截图、规则未命中或计划生成称为整套测试通过。

## 执行时机

选择全部或多项检测时，默认执行顺序为 **1代码 → 3点击 → 4流程 → 2UI**，只执行用户选中的项，UI放在最后。检测编号保留原定义；用户明确指定其他顺序时遵从。前序检测需要修复且已获授权时，先完成修复及相关重测，再对最终代码版本进行UI检测，避免截图和布局结论过期。

## 统一交付要求

面向用户的报告必须遵守 [检测报告统一规范](reporting.md)，使用固定模板、状态和必填证据；本文件的专门要求填写在模板对应栏目，不另创报告格式。

## 首次通道检查与失败分支

先验证当前机型的一页采集、截图和恢复，读图确认通道正常，再扩大到既定多机型计划；这一页不是完整UI结论。全页/多机型可能超过执行工具前台时限，使用其后台能力保存日志和任务进度；不固定要求某个agent。

端口、权限和启动失败统一按[本机调试通道](debug-channel.md)处理，按实际获准的执行能力准备通道。短时间内无法建立时明确阻塞；可用的官方CLI当前机型检查继续，多机型标未覆盖，不以单机型代替。机型模块按能力定位，不固定打包哈希；能力缺失或候选不唯一时停止并说明。
