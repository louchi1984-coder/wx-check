# 连接授权与登录故障处理

开始测试前读取本文件。连接授权、微信账号登录、项目可用性是三个不同状态，不能混成一个“等待登录”。

## 有限等待

只读状态查询单次最多20秒；整个自动登录诊断最多90秒（用户实际扫码等待单独计算）。调用超时立即返回，不再启动相同调用叠加等待。用户未完成确认时暂停并明确说明具体待办，不在后台不断重试；等待期间不计测试通过。

记录实际CLI绝对路径、工具版本、clientName、操作系统用户及会话、查询时间、原始错误类型和任务ID。沿用已授权clientName，不因agent名称、技能重命名或不同命令自动换身份。工具JSON的ok=false、CONNECT_ERROR、pending均不算成功，即使进程退出码为0。

## 状态分支

1. CLI无法连接或授权超时：先核对GUI与CLI是否来自同一安装、同一用户及会话，检查是否出现客户端授权请求。不要直接要求扫码；不要在每次状态查询失败后重新auth。Windows远程会话尤其核对Session 0与用户桌面。
2. 连接成功且loginExpired=true：经授权只触发一次login，保留任务ID；展示工具返回的二维码。用户说扫码后查询任务结果并重新读登录状态，最多两次有界查询。
3. GUI显示登录、CLI仍未登录或超时：这是状态不一致，不能继续循环登录。先核对安装、clientName及用户会话，再做一次只读复查；若仍不一致，保存两边时间和证据，明确报告“登录通道未验证”，暂停依赖登录的检测。不能把重复扫码、无限轮询、强杀或清认证当作处理。
4. CLI确认loginExpired=false：继续列项目与核对AppID。只要后续CLI操作可用，不因某个GUI创建面板未同步就阻断全部CLI检测；需要该GUI面板时单独标记未覆盖。

90秒内必须交付具体状态、已检查事实和下一步。需要用户动作时说明“哪个窗口、哪个按钮、为什么”，不能只说GUI与CLI不一致。未经授权不清登录态、不重启、不切用户、不重置配置。不得宣布故障修复，除非原场景复测成功。

## 已复现的旧CLI二维码错误

旧CLI出现“二维码输出路径无效(code 17)”或“EISDIR(code 10)”时，属于二维码生成失败，不是等待扫码。立即结束等待并记录原错误。路径参数要求具体文件时不能传目录；先核验父目录存在、目标不是目录。不要在未修正参数时重试。

本skill优先使用 `wechatide -c <已授权clientName> login --type image`，读取其返回的图片与taskId，而不是混用旧CLI的login参数。返回图片内容时保存为工程外具体图片文件；图片没有返回就不要求用户扫描CLI二维码，转入下面的GUI兜底。仅在当前已获登录授权时触发，不能为了验证路径清认证或重复登录。

## GUI手动扫码兜底

CLI二维码生成失败、无法展示，或自动登录诊断达到90秒仍未确认登录时，结束CLI登录尝试，调出同一安装、同一用户会话的微信开发者工具登录界面，让用户直接扫描界面中的真实二维码。登录请求已获授权时无需重复询问同一次扫码；需要退出账号、重启或清理认证时另行取得授权。

必须确认实际显示的是登录界面，再告诉用户在哪个窗口扫码；项目列表不能证明已经登录，也不能当作二维码界面。若当前工具能力无法调出或识别登录界面，明确说明限制并给出手动打开步骤，不能假称已调出。不依赖特定agent或操作系统：使用当前环境可用的应用启动、窗口控制能力；Windows须使用用户可见的桌面会话。

只能原样展示工具返回或GUI显示的真实二维码，禁止手绘、猜测、重建二维码或用占位图代替。用户扫码等待期间不自动重复login，不无限轮询。

用户确认扫码完成后，以单次最多20秒的CLI状态查询验证登录；若保留了CLI任务ID，也读取任务结果，总计最多两次有界查询。确认loginExpired=false后继续选择工程、确认AppID、打开／导入工程；GUI明确已登录而CLI仍未确认时，按状态分支3检查连接目标并报告阻塞，不再次要求扫码。GUI仅用于登录兜底，不改变后续通过CLI或脚本执行测试的方式。

登录成功后必须转入 [user-flow.md](user-flow.md) 的“登录后的必经步骤”。确认登录只允许继续准备流程，不能直接运行检测、创建业务工程或修改代码。
