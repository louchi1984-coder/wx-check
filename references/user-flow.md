# 用户引导与会话流程

适用于任何能读工程、执行本地命令和审阅证据的 agent 或人工执行者；不要求特定聊天软件、模型、插件或机器品牌。先发现当前操作系统、开发者工具版本和可用通道，再选适配器；不要把历史 Mac 验证环境当作安装要求。没有固定 CPU、内存或显卡门槛，按实际就绪状态与工具要求判断，超时不直接归因于硬件。

## 开始与选项

先定位工具、核验客户端连接授权和微信账号登录、识别目标工程，再询问用户是否有 AppID；有则确认，没有则调出新建／导入界面，让用户手动选择“测试号”，完成后核对工程配置。已经确认的工程与选择沿用。向用户用四句话介绍：1代码有没有写对；2界面显示正常不正常；3按钮点了有没有反应；4像真人一样用一遍顺不顺。提供单项、全部或继续上次；用户已给出检测编号时直接执行，不重复选择。信息能通过只读发现就先发现，缺少的信息一次集中询问。

## 登录后的必经步骤

登录成功只完成环境准备，不等于获得工程操作、检测或修复授权。严格按下面顺序推进，不能从登录直接跳到测试脚本：

1. **确定目标工程**：沿用用户已指定的工程；否则只读列出已有项目供选择。没有项目时询问要导入的工程目录。不能自行选最近项目、示例工程或新建业务工程。
2. **确认 AppID**：询问是否有要使用的 AppID；有则提供或确认，没有则引导在开发者工具界面手动选择测试号。已明确回答的沿用。
3. **打开／导入指定工程**：目标和 AppID 确认后才进行，已有项目直接复用，避免重复导入。打开后核对实际路径和 AppID；仅做判断是否就绪所需的编译，不把这一步算作完整检测，也不开始业务点击。
4. **选择检测范围**：介绍代码、UI、点击、流程四类，询问本轮做哪类或全部。用户先前已明确指定则直接沿用；仅说“检查小程序”时不能擅自默认检测1和2。
5. **确认执行条件后检测**：说明已选工程、AppID类型、检测范围及必要的数据影响，检查相关副作用授权。上述必要信息缺失时停在对应步骤等待回答；只做不依赖答案的只读准备。均已明确时直接执行，不额外索取一次重复确认。

用户只说“扫码了”“登录好了”“继续登录”仅表示推进当前登录步骤；不能据此扩展为全部检测、业务数据写入或代码修复。用户说“继续”时恢复此前明确的阶段和范围，不重新猜测任务。检测后先报告问题及建议，修复按已有明确授权执行；没有授权时询问修复范围。

执行前简述范围、机型与数据影响。模拟器预设不是对用户真实硬件的限制；按本机可用较新预设选择主流代表，UI仍小中大各两款、重点宽屏／折叠展开，缺预设明确调整清单，不要求特定手机型号。相同业务逻辑不用重复遍历全部UI机型。

集中说明写入、删除、清空、剪贴板、服务端提交等副作用，并一次询问本轮需要的授权；已授权范围不重复询问。需要安装、登录、清认证或重启时说明具体动作与原因，不能假定测试授权包含所有操作。

登录排障按 [login.md](login.md) 执行：自动诊断总计不超过90秒，区分连接授权、扫码登录和项目可用性；GUI与CLI不一致时必须给出明确处理分支，不能无限等待。

## 检测顺序

选择全部或多项检测时，默认执行顺序为 **1代码 → 3点击 → 4流程 → 2UI**，只执行用户选中的项，UI放在最后。检测编号保留原定义；用户明确指定其他顺序时遵从。前序检测需要修复且已获授权时，先完成修复及相关重测，再对最终代码版本进行UI检测，避免截图和布局结论过期。

不能用默认的组合体检命令提前执行UI；代码阶段仅运行代码相关检查，UI阶段使用独立UI入口并完成读图。用户只选UI时，必要的打开、编译与就绪检查属于准备步骤，不自行增加其他检测。

## 执行中与异常

正常步骤自动推进，用普通语言报告有意义的发现；不把工具协议、模块名字与临时探针塞进用户操作流程。区分应用缺陷、通道故障和未覆盖。出现页面实例不一致时停止业务操作；在授权内修复并实际重测，无法修复时说明具体障碍及下一步，不反复运行同一失败命令、不以零采集计通过。

保持工程、AppID类型、检测项目与任务进度、机型计划、授权、代码版本、证据时间和输出路径的会话记录，保存在工程外。记录不是凭空授权依据：保留用户原话或可核对的会话出处。暂停立即停止新增操作，收尾保护已进行的数据写入；继续时读取记录并核对环境和版本，只补未完成项。代码变更后重测受影响项目，不把旧结果冒充本轮结果。换工程需重新核对归属和副作用，不能沿用上一工程的写入权限。

## 结果与修复衔接

先说发现什么、哪些需要修复，再给证据和未覆盖项，技术细节放附件。检测结束不等于全部通过。流程测试必须交付完整任务清单及各状态；截图已保存不等于已读图。按测试项目定义归类，不把工具诊断当UI测试。

用户要求修复时按 repair.md 判断检测项修复或完整修复，修复后重测相关场景，并更新问题状态；没有修复授权时报告建议，不自动扩大到业务代码修改。报告必须区分当前已验证与环境假设，包括不同操作系统。

## 统一交付要求

面向用户的报告必须遵守 [检测报告统一规范](reporting.md)，使用固定模板、状态和必填证据；本文件的专门要求填写在模板对应栏目，不另创报告格式。

## 用户可见的步骤

以SKILL.md的步骤表为执行入口，每阶段说明当前步骤、下一动作或等待用户做什么。登录后依次选择工程、AppID、打开工程、选择检测范围，不跳步。检测1→3→4→2，已选项逐项交付再汇总。项目名称只用“代码测试、UI测试、点击测试、流程测试”；说明操作时用“实际点按钮”“按正常使用步骤测一遍”“修改后再测”等普通话，不把内部技术术语直接交给用户。
