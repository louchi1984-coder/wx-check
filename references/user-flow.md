# 用户引导与会话流程

适用于任何能读工程、执行本地命令和审阅证据的 agent 或人工执行者；不要求特定聊天软件、模型、插件或机器品牌。先发现当前操作系统、开发者工具版本和可用通道，再选适配器；不要把历史 Mac 验证环境当作安装要求。没有固定 CPU、内存或显卡门槛，按实际就绪状态与工具要求判断，超时不直接归因于硬件。

## 开始与选项

先定位工具、核验客户端连接授权和微信账号登录、识别目标工程，再明确测试号／真实 AppID。已经确认的工程与选择沿用。向用户用四句话介绍：1代码有没有写对；2界面显示正常不正常；3按钮点了有没有反应；4像真人一样用一遍顺不顺。提供单项、全部或继续上次；用户已给出检测编号时直接执行，不重复选择。信息能通过只读发现就先发现，缺少的信息一次集中询问。

执行前简述范围、机型与数据影响。模拟器预设不是对用户真实硬件的限制；按本机可用较新预设选择主流代表，UI仍小中大各两款、重点宽屏／折叠展开，缺预设明确调整清单，不要求特定手机型号。相同业务逻辑不用重复遍历全部UI机型。

集中说明写入、删除、清空、剪贴板、服务端提交等副作用，并一次询问本轮需要的授权；已授权范围不重复询问。需要安装、登录、清认证或重启时说明具体动作与原因，不能假定测试授权包含所有操作。

## 执行中与异常

正常步骤自动推进，用普通语言报告有意义的发现；不把工具协议、模块名字与临时探针塞进用户操作流程。区分应用缺陷、通道故障和未覆盖。出现页面实例不一致时停止业务操作；在授权内修复并实际复验，无法修复时说明具体障碍及下一步，不反复运行同一失败命令、不以零采集计通过。

保持工程、AppID类型、层级与任务进度、机型计划、授权、代码版本、证据时间和输出路径的会话记录，保存在工程外。记录不是凭空授权依据：保留用户原话或可核对的会话出处。暂停立即停止新增操作，收尾保护已进行的数据写入；继续时读取记录并核对环境和版本，只补未完成项。代码变更后重测受影响项目，不把旧结果冒充本轮结果。换工程需重新核对归属和副作用，不能沿用上一工程的写入权限。

## 结果与修复衔接

先说发现什么、哪些需要修复，再给证据和未覆盖项，技术细节放附件。检测结束不等于全部通过。第四层必须交付完整任务清单及各状态；截图已保存不等于已读图。按四层定义归类，不把工具诊断当界面测试。

用户要求修复时按 repair.md 判断单项或完整闭环，修复后复验相关场景，并更新问题状态；没有修复授权时报告建议，不自动扩大到业务代码修改。报告必须区分当前已验证与环境假设，包括不同操作系统。
