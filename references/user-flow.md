# 用户引导与会话流程

适用于能读工程、调用微信开发者工具并审阅证据的执行者。先发现本机工具与通道，不套用历史Mac／Windows路径、机型或硬件配置。

## 登录后的必经步骤

已确认的步骤沿用，不重复询问：

1. 确定用户指定工程；未指定时列已有工程供选择，没有时询问导入目录，不自行选最近工程或新建业务工程。
2. 问是否有AppID；有则确认使用哪个，没有则让用户在开发者工具界面手动选测试号，读取最终工程配置核对。
3. 打开或复用指定工程，核对实际路径、AppID和运行状态。代码测试使用完整模式；现有简洁窗口不会因open返回reuse转换，重开按授权处理。
4. 确认做代码、UI、点击、流程中的哪项或全部；用户已指定就执行。集中说明需要的数据影响并确认缺少的授权，已授权范围沿用。

找到工具、连接授权、微信登录分别核验，登录处理见[login.md](login.md)。“扫码了”只推进登录；“继续”恢复已有阶段和范围，不扩大为全部检测或修复。缺信息时继续不依赖它的只读准备，必要问题集中询问。

向用户介绍只用四句话：代码有没有写对；界面显示正不正常；按钮点了有没有反应；像真人一样用一遍顺不顺。登录失败时展示真实二维码或调出实际窗口，不画二维码、不无限等待。

## 执行与暂停

多项默认代码→点击→流程→UI，用户指定其他顺序时遵从。一次只执行当前一项，先明确其目标和检查清单，检测后核对覆盖，保存并交付该项报告，才进入下一项；不能提前启动其他检测。已有修复授权时修复并测试相关结果、更新该项报告后继续；UI测最终代码版本。只选UI时必要的编译和就绪属于准备，不自行增加其他测试。

执行者根据业务和实际页面选择步骤，直接使用适用接口；批量脚本可选，不把它的跳过、超时或静态识别范围当整项测试的结论。主流机型沿用已确认计划，业务逻辑不重复所有UI机型。

出现问题说明应用故障、工具故障或具体缺口，以及下一步。定位失败查看实际元素，安全条件恢复后继续独立任务。涉及数据、连接和授权的边界按[execution.md](execution.md)处理。

保留当前工程、检测范围、授权出处、进度、代码版本和证据路径的工程外会话记录。暂停停止新增操作并保护已产生的数据；继续核对状态，只补未完成部分。换工程重新确认数据操作范围，代码变化后重测受影响任务。

## 交付

报告按[统一规范](reporting.md)，先说发现什么、是否该修、哪些还没测，再给证据。技术日志作附件；全部任务已识别或截图已保存都不等于测试完成。修复按[repair.md](repair.md)和已有授权，未经授权不修改业务源码。
