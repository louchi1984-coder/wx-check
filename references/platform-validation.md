# 跨平台环境与验证

先发现操作系统、Node版本、开发者工具安装和内置wechatide CLI。执行者不限agent或聊天应用；不指定CPU、内存、显卡门槛。缺环境时列出具体缺失项，不先让用户买硬件。

环境入口：WECHATIDE_BIN（实际可执行CLI）、WECHATIDE_CLIENT（沿用已授权身份）、WECHATIDE_DATA_DIR（实际工具数据目录）、WECHATIDE_MODULES_DIR（工具 app.asar/js 虚拟目录）、WECHATIDE_DEBUG_PORT（已授权本机调试端口）、WECHATIDE_PRECISE_MODELS（小小中中大大六个预设完整名称JSON数组）。路径来自本机发现或用户提供，不能把Mac路径替换分隔符后当Windows已可用。Node、WebSocket与CLI运行要求需实际核验。

已知边界：诊断读取器按模块内容识别服务并验证运行时接口，不固定哈希文件名或版本；机型 live 适配器仍需核对本机模块与API。Windows 的 .cmd/.bat CLI 通过 PowerShell 编码参数启动；已在实际 Windows 上验证 findCli 可正确读取官方 wechatide.cmd 帮助。Windows进程组终止与POSIX不同，超时后子进程清理要实测。Windows数据格式／项目路径映射也须验证，不能直接修改猜测到的配置。缺支持时拒绝该通道，仍可执行已验证的静态检测。

Windows验收顺序：
1. Windows实机记录OS、Node、工具版本及发现路径；执行CLI帮助、登录状态和项目识别，不打印账号秘密。
2. 用已有或经授权测试号工程执行代码测试；验证路径含空格和中文、进程启动与超时失败不会遗留危险操作。
3. 核对项目唯一定位、实际页面ID、尺寸；验证同窗口机型切换、截图、精测读图、恢复及异常恢复。
4. 执行点击与完整任务清单，核验真实结果；可靠备份和异常恢复必须逐键确认，副作用授权沿用明确范围。
5. 保存Windows原始日志、截图、问题和覆盖状态；每项PASS/FAIL/NOT_RUN，不将Mac报告、静态审查或模拟win32当Windows实机通过。

远程Windows首次授权要在用户桌面会话中发起。SSH可能启动Session 0的后台窗口，导致看不到确认/二维码；先核对会话和窗口，不清认证、不重复扫码。按获得的授权在桌面启动工具；客户端连接授权与微信账号登录分开核验，pending不等于成功。数据目录来自实际安装发现，不能猜测。
